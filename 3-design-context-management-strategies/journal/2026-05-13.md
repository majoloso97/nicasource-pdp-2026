### Journal
This article is a great compendium of prompt engineering techniques. It's nice how it presents prompting as an empirical but systematical process, trying to drive the model behavior through context structure. I like it doesn't just present prompting as magical tricks that only a few know.

A recurring idea is that prompting is very dependent on the model being used. Some models might work well with a prompt an another might have sub-ideal performance with the same one. This really reminds me of hyperparameter tuning in more 'traditional' machine learning. You never know at the start what learning rate to set at the beginning, and you need to iterate repeatedly to find the optimal value.

The progression from zero to few-shot prompts, to chain-of-thought prompting help to understand how the prompting shapes the behavior during inference, instead of explicitly training the model for every task.

Chain-of-thought prompting was especially interesting because it demonstrates that reasoning quality can improve just by asking for intermediate reasoning steps. I feel the ReAct paper I have on the reading queue will definitelly add more context to this concept. 

Another thing I noticed, again, is how many current LLM practices already existed conceptually in these earlier prompt engineering discussions, such as RAG, tool usage, output constraints, etc. And also, how some of these techniques resemble traditional machine learning model creation process: ensemble models, tuning, etc. This again makes the buzzwords around modern "AI engineering" to feel like scaling and orchestration over these prompting principles.

Two key aspects: where the key info is within the prompt, like Lost in the middle mentioned is as important as its structure: format, examples, order. Another similarity I find to model development: experimentation, there's no best prompt overal. We can just aim to find a local minima when optimizing. We won't know whether that's the overall best result.

Overall, this article helped organize many prompting concepts into a more coherent mental model. Prompt engineering is about writing better instructions, yes, but also, it's about controlling context, inducing reasoning behavior and designing reliable interactions around models that are inherently probabilistic.

### Journal
After going through these papers and articles together, I think the biggest realization is that most modern AI systems are not really defined by the model alone, but by the orchestration around it.

A lot of what people now call agents is fundamentally iterative orchestration: reasoning, evaluation, state management, retries and adaptation. From a high level this looks simple, but I think implementation matter as much. Engineering around this flow creates relevant complexity, and can cause poor performance if done incorrectly.

For example, I imagine: having a great prompt, working well, but we break it when trying to improve it. No versioning available, we might be lucky and find it somewhere, else, we need to reiterate from scratch. Or, what if we give the model a lot of tools and none of them are really well tested? 

The "Lost in the Middle" paper definitely changed how I think about context windows. Even if I thought of the 'attention' the LLM as an exponential curve, it turns out is more like a flat cuadratic equation, "U" instead of "J" shaped, in other words. It's important to remember that the placement of information has a huge role: better to include most relevant chunks at the start. Also, even if the context contains some info, it doesn't guarantee the LLM will pay attention to it. That's very relevant for designing the state around LLM flows (how to organize chat history, where to include things like user preferences, etc).

Another thing I found interesting is how the APE framework introduces the idea of prompts as 'interfaces'. And how we can manage them similar to configuration files rather than just a list of instructions. As such, it's sensible to be careful when managing prompt changes, as they might introduce unwanted changes. This paper also made me think about how prompt generation automations are great and can find even better prompts that human, but that loop can be just as good as the evaluation tools provided.

A good thing overal, at least to me, is that current ecosystems introduce sometimes overcomplicatd terminology. However, everything can be easily understood by learning the primitives, and thinking in terms of reusable pieces. Frameworks like LangChain seem to be just doing that, in a way that is more ergonomic than building all this by hand every time. That said, I feel the key parts to keep in mind can be summarized as:
    - prompt construction
    - retrieval
    - decomposition
    - loops
    - memory management
    - tool usage
    - planning
    - evaluation
    - orchestration

Each of these pieces has its challenges, but it makes the whole deal feel manageable, a lot can be abstracted when we consider that we 'just' need to:
    - control context
    - evaluate behavior
    - expect and manage uncertainty
    - orchestrate flows around such uncertainty

Evaluation and orchestration are key, regardless of the model, prompt strategy, context curation.
